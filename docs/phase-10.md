# Phase 10 controlled serendipity

The serendipity engine chooses weighted recent/important/unresolved/dormant/random/novel anchors, compares structurally nearby and randomly sampled distant-domain experiences, and frequently returns no proposal. Successful-strategy analogies include source IDs, differences, supporting episodes and counterexamples. A separate critic and confidence/novelty/utility/evidence thresholds decide whether the result remains candidate. Epistemic type is always hypothesis, never verified fact or causation. Storage uses the Phase 9 insight/provenance schema, so no new DDL is required.

Acceptance verifies NONE without evidence and an evidence-supported software/workflow analogy, with differing domains retained and independent critic verdict. Example: POST `/v1/serendipity/run`. The RNG is injectable for deterministic evaluation.

Limits: this initial explorer focuses on structural experiences and shared successful strategies; its model interface permits richer analogy proposals under the same gates. It never executes the suggested strategy. DREAMER worker orchestration follows the same authorization boundaries.
