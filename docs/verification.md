# Verification and practical limits

The implementation was tested progressively before advancing through the twelve phases. The final suite contains **80 passing tests**, on both Windows Python 3.11 and Linux Python 3.12, with PostgreSQL and Redis enabled and no skipped tests. Ruff checks and formatting also pass. One upstream Starlette/httpx test-client deprecation warning remains; live HTTP tests independently exercise real TCP requests.

The suite covers canonical schema/time/confidence validation; transaction rollback; concurrent duplicate writes; model-space isolation; namespace, agent, project and operation scopes; private derived evidence; rolling-buffer isolation; exact BM25 candidate recovery; entity-vector projections; temporal supersession and as-of recall; contradictions; episodes; 120-day structural analogy; repeated-evidence procedures; new-session and cross-agent transfer; 100-episode hidden failure associations; counterexamples; confidence revision; bounded graph/serendipity; decay; clusters; prospective recall; source injection treated as data; deletion; durable jobs; Redis working references; outbox dispatch; and non-superuser RLS.

Live acceptance starts Uvicorn as a subprocess and calls FastAPI over TCP, persisting and recalling through PostgreSQL/pgvector, building an empty-session context package, then deleting and checking absence. A separate Redis integration proves deleted records cannot be reconstructed from stale working references. The local load smoke uses 20 requests with concurrency 4 and reports zero errors. Exact observed timings are in load-test-results.json; they are not a capacity guarantee.

The deterministic lexical benchmark uses 100 records and 20 exact-identifier queries with the explicit hash-test model. Recall@5, MRR and NDCG were 1.0; Precision@5 was 0.2 because each query has one relevant item. Timings are in benchmark-results.json. These results establish exact-fixture behavior, not natural-language semantic quality or production accuracy.

The Python 3.12 Docker image builds successfully. The default API role is non-superuser and separate from administrative migrations/bootstrap. The RLS test demonstrates default-deny, authorized namespace access and exclusion after changing namespace context. The development database remains bound to localhost:55432; Redis binds to localhost:6379.

Migration 0012 separates durable source evidence from the ten-message rolling buffer. Source records survive rolling-context pruning and are purged on forgetting; erasure also clears raw session content so assistant paraphrases cannot retain the deleted source. Other surviving memories may therefore retain source IDs whose original content was erased. Namespace deletion clears all retained raw sources. A claimed background job must recheck its lease inside the mutation transaction, so a canceled raw-input job cannot repopulate deleted information.

Before production, evaluate real model endpoints and domain corpora, size and index the exact-retrieval adapters, perform sustained capacity testing, configure hosting TLS/encrypted disks/backups and secret rotation, choose backup deletion retention, and enforce distributed limits at ingress for multiple replicas. Broader pattern miners, complex task segmentation and cross-user federation remain explicitly scoped extensions. None are silently removed from the master target or claimed proven by these fixtures.
